# 고전지혜 (古典知慧) — 설계 문서

## 1. 비전

"역사는 거울이다" — 유저가 자신의 고민을 입력하면, 사서오경과 사기 속에서 비슷한 고민을 겪었던 옛 인물들의 이야기를 찾아, 그들이 어떻게 살았고 어떻게 해결했는지를 이야깃거리로 풀어주고, 현인들의 솔루션과 방향도 함께 제공한다.

## 3. 데이터 플로우

1. 유저가 `#🧩-내-문제-꺼내기` 채널에 고민을 작성
2. Hermes Gateway가 메시지 수신 (channel_prompt로 해당 채널 자동 응답)
3. Skill이 고민 키워드 추출 → RAG 서비스에 검색 요청
4. RAG 서비스가 FAISS 인덱스에서 top-K 관련 구절 반환
5. Skill이 관련 구절을 컨텍스트로 사용하여 LLM으로 지혜 생성
6. 응답을 Discord에 게시

## 4. 기술 스택

| 구성요소 | 기술 | 이유 |
|---------|------|------|
| RAG 서비스 | Python FastAPI | 경량, 서버 리소스 최소 |
| 임베딩 | sentence-transformers (paraphrase-multilingual-MiniLM-L12-v2) | 한국어+한문 지원, 경량 |
| 벡터DB | FAISS | 메모리 내 동작, 추가 DB 불필요 |
| 서비스 관리 | systemd user service | Docker 없이 운영 |
| LLM | Hermes 기본 모델 (mimo-v2.5 / openrouter) | 기존 인프라 활용 |
| Discord | Hermes Gateway (기존) | 새 봇 불필요 |

## 5. RAG 서비스 API

```
GET  /health          → 서비스 상태
POST /search          → 관련 구절 검색
     Body: { "query": "사업이 잘 안돼요", "top_k": 5 }
     Response: {
       "results": [
         {
           "text": "공자왈 삼십이립...",
           "source": "논어_원문.md",
           "section": "위정제이",
           "score": 0.87
         }
       ]
     }
POST /index/rebuild   → 인덱스 재구축 (관리자용)
```

## 10. 제약 및 고려사항

- 서버에 Docker 없음 → systemd user service 사용
- Python 3.12 환경 → 별도 venv 구성
- 임베딩 모델은 경량 다국어 모델 사용 (서버 리소스 한계)
- 사기_원문.md가 2.2MB로 가장 큼 → 청킹 전략 중요
- 한문 원문은 한국어 임베딩과 의미 거리가 멀 수 있음 → 한국어 번역본 우선 검색
